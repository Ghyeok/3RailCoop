# SPEC — 구현 체크리스트

구현할 일을 항목 단위로 관리한다. 진행 절차와 테스트 정책은 `AGENTS.md`를 따른다.

## 규칙

- **항목 크기:** 한 세션 안에 끝낼 수 있고 PR 하나로 묶이는 기능 단위. 더 크면 나눠서 등록한다.
- **ID:** `S-<마일스톤 번호><두 자리 순번>`. S-000은 공통 기반 작업.
- **상태:** `후보`(완료 기준 미승인) → `대기`(착수 가능) → `진행 중` → `보고됨`(사용자 승인 대기) → `완료`(체크).
- **체크:** 완료 기준 확인 → 구현 → 자동 테스트 → 회귀 테스트 → 코드 리뷰 → 결과 보고를 통과하고 사용자가 승인했을 때만 체크한다. 체크와 결과(PR 번호) 기록은 병합 직전에 해당 브랜치에서 한다.
- **`[수동]`:** 자동화할 수 없어 수동 검증 절차로 테스트하는 항목.
- **기존 구현 검증:** 이 문서 도입 전에 작성된 코드. 파이프라인을 통과하기 전까지 완료로 보지 않는다.

항목 형식:

```
- [ ] S-xxx 제목
  - 기획 근거: Game_Design.md §
  - 완료 기준: 관찰 가능한 조건
  - 테스트: 자동 테스트 / [수동] 절차
  - 상태: 후보 | 대기 | 진행 중 | 보고됨 | 완료
  - 결과: 커밋·PR, 보고 요약 1~2줄
```

## MVP 목표와 진행 순서

**MVP 완료 기준 (D-007):** 1명의 로컬 플레이어가 Steam과 관계없이 한 기기에서 두 플레이어를 조작해 짧은 테스트 스테이지를 진행한다. 이동(쿨타임 포함), 합체·분리, 장애물 회피, 게임 오버와 재시도, 목표 거리 클리어까지 플레이할 수 있다. 판정은 틱 없이 실시간으로 한다.

- MVP에서 제외: Steam·네트워크(S-401, S-701, S-402, S-702, S-703), 틱 판정 구조(S-201·S-102·S-202), 사망·암살 기록 UI(S-601), 무작위 패턴(S-501), 해금(S-704).

**진행 순서 원칙:**

- 이동과 합체·분리, 고정 장애물, 게임 오버·재시도를 작은 구간에서 먼저 확인한다.
- 규칙 로직은 MVP에서도 MonoBehaviour와 분리된 순수 C#으로 작성해, 네트워크 단계에서 판정 시점만 틱 구조(S-201)로 바꿀 때 규칙 코드를 재사용한다.
- MVP를 마친 뒤 Steam 친구와 온라인으로 테스트해 네트워크 지연과 조작감을 따로 살펴본다.
- 무작위 패턴, 암살 통계와 스테이지 해금 등의 범위와 추가 순서는 테스트에 필요한 정도를 고려해 정한다.
