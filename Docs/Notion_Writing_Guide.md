# Notion 개발 일지 작성 가이드

이 문서는 `3 Rail Coop` Notion 페이지의 개발 일지를 바탕으로 정리한 작성 가이드다. Notion 글을 작성할 때 참고하며, 사용자가 별도로 요청한 형식과 내용이 있으면 그 요청을 우선한다.

## 기본 구성

1. **개발 개요**: 개발 날짜와 목표를 짧게 적는다.
2. **개발 과정**: 작업을 순서대로 나누어 번호가 있는 제목으로 정리한다.
3. **개발 결과**: 확인한 결과가 있을 때 이미지나 설명을 덧붙인다. 아직 검증하지 못한 내용은 미확인 상태로 적는다.

Notion에서는 개발 과정의 각 작업을 제목이 있는 토글로 구성한다. 내용이 길면 버튼이나 기능별로 하위 토글을 사용한다.

## 글을 전개하는 방식

- 구현이 필요한 상황이나 목표를 먼저 설명하고, 선택한 방법과 이유를 적는다.
- 작업 순서에 맞춰 코드 또는 Unity 설정을 소개한 뒤, 주요 함수와 값이 어떤 역할을 하는지 설명한다.
- 코드 블록에는 설명에 필요한 메서드나 클래스의 실제 코드를 넣는다. 일부만 보여줄 때는 생략된 범위가 오해되지 않게 표시한다.
- 함수, 변수, 클래스, 컴포넌트, 파일명은 인라인 코드로 표시한다. 중요한 역할이나 결정은 굵게 강조한다.
- Unity 씬이나 UI를 다룰 때는 필요한 경우 Hierarchy, Inspector, 실행 화면의 이미지와 함께 설정 내용을 설명한다.
- 미구현 항목, 테스트하지 못한 내용, 다음 작업이 있다면 현재 상태를 분명히 적는다.

## 문체

- 한국어로 간결하게 설명하고, Steam·Unity·NGO 등의 기술 용어와 API 이름은 원래 표기를 유지한다.
- 구현한 내용은 “연결했다”, 동작 원리는 “호출한다”, 작업 흐름은 “생성해보자”처럼 자연스럽게 서술한다.
- 한 문단에는 하나의 흐름이나 개념을 담고, 필요할 때 짧은 목록으로 정리한다.
- 코드의 실행 순서, 입력과 결과, 다른 컴포넌트와의 연결 관계를 구체적으로 설명한다.

## 작성 시 확인할 점

- 현재 프로젝트 코드나 제공된 자료를 확인해 실제 구현과 글의 내용이 일치하도록 한다.
- Steam 로비 입장, NGO 연결 시작, NGO 연결 완료처럼 서로 다른 시점을 구분한다.
- 직접 확인하지 않은 테스트 결과나 없는 스크린샷을 만들어내지 않는다.
- 기존 일지의 과거 코드가 현재 코드와 다르면 해당 일지의 작성 시점과 현재 상태를 구분한다.

## 간단한 작성 예시

```text
<개발 개요>
- 개발 날짜: YYYY.MM.DD
- 개발 목표: 이번 작업의 목표

<개발 과정>
1. 첫 번째 작업
   작업이 필요한 이유와 선택한 방법
   관련 코드 또는 Unity 설정
   주요 동작과 결과 설명

2. 두 번째 작업
   ...

<개발 결과> (확인한 내용이 있을 때)
테스트 결과 또는 실행 화면 설명
```
